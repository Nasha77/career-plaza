Humancareers · Career Plaza

How Career Plaza works

A plain-language guide to what happens inside the game, from the moment a student opens it to the growth record they leave with.

The idea

Students try a real kind of job for a few minutes, notice what they used and enjoyed, and leave with a record of it. Nothing is graded.

Career Plaza is a small 3D town square with four buildings. Each building is an internship based on a real job posting. Inside, a manager gives the student a task, the student does it, and the manager reacts. At the end, everything the student did is collected into a growth record.

The big loop

What a student does, start to finish

  1. Self-checkA one-minute check: "How confident am I?" and "What draws me?" Optional.
  2. Pick a buildingAny of the four, in any order. No wrong choice.
  3. Do the taskChoose an approach, look at what it turned up, write a short answer.
  4. See the recordWhat you used, enjoyed, and could try next.

↺ Go back to the plaza and try another building. Revisiting a building brings a new twist.

Inside one building

One scenario, step by step

Example: the Harbourfront Resort, where the student is a Communications Intern working with Priya.

1

The manager sets the scene

Priya: "Welcome aboard! Our volunteer day at a senior activity centre is in two weeks, but only 12 of 40 spots are filled."

2

The student picks an approach

Three options, each leaning on a different skill. For example, "Look at last year's volunteer data" uses Analysis. The manager reacts straight away in their own voice, and every later action (skipping, revising, rating) gets a reaction too.

3

They see what their approach turned up

Front Office14
Food & Beverage9
Housekeeping3
Security0

Worth noticing: night-shift teams barely joined.

Practice data. A "Your task" box above it keeps the situation, any new twist and the chosen approach on screen while the student writes, so nobody loses track.

4

They write a short answer

For example, the first line of a message to staff. This becomes a work sample in the growth record.

5

Coaching, only if it's clearly weak Smarter with AI

If the answer is only a few words or off-topic, Priya gives one tip and offers "Revise my answer" or "Keep it and continue". Revising is always optional, and both drafts are kept.

6

A follow-up question AI only

Priya: "Why did you lead with the seniors rather than the date?"

Like a real manager asking about your thinking. The student can reply or skip.

7

Feedback and skill tags

Priya reacts to the choice. Skill tags float up, like + Analysis, to show which skills the student just used.

8

A reflective question, then ratings

"Did digging into the data feel satisfying or slow?" Then the student rates how much they enjoyed it and how confident they felt, from 1 to 5. These are feelings, not marks.

9

Learn more

A short list of real links about this kind of work, plus NTU's career office. Then back to the plaza, where the building lights up on the career map.

The output

The growth record

Every finished scenario is saved. The growth record turns them into a picture of the student, built only from what they did and said:

What you tried

Each internship, the approach chosen, and the student's own words (first draft and revision).

Then and now

The start self-check next to what actually happened. For example: "You rated yourself lower on Analysis than you felt when using it."

Skills across fields

Which of the four skills (Research, Communication, Organisation, Analysis) showed up, and in which buildings. One skill can work in very different jobs.

What's next

Skills to grow, ideas to try next, links to learn more, and (with AI) a short personal summary.

The AI

What the AI adds, and how it's kept safe

The game works fully without AI. The AI makes the managers feel like real people: it reads what the student actually wrote and responds to it, in each manager's personality.

Each manager has a personality

Warm, upbeat, people-first. "Yay, I'm so glad this one clicked for you!"

Calm, precise, dry humour. "I'll note your interest. Accurately."

The guardrails

  • ⌂Server side only. The AI never runs in the student's browser. It runs in a small server function (on Vercel for the live link, or on a laptop for development), and the GitHub Pages copy has no AI at all.
  • ✦The key stays private. It lives in a private setting on Vercel, or in a hidden file (.env.local) on a laptop. It is never uploaded to GitHub and never sent to the browser.
  • ✎No open chat. Students only fill in short boxes. Their text is treated as an answer to react to, never as instructions to the AI.
  • ✓Every reply is checked. Replies must be short, in a fixed format, with no code, links, scores or "best fit". Anything else is thrown away.
  • ⚑Only the game can use it. The live function refuses requests that don't come from the site itself, and limits each visitor to 30 AI calls per 10 minutes.
  • ↺It never breaks the game. If an AI reply hiccups, the server tries once more. If that fails too, or the AI is off, or a check fails, the written line from the content file is used instead.

Common questions

Quick answers

Why are there no scores?

The goal is exploration, not judgement. Students should notice what they enjoy and what they're good at, which can be different, without feeling tested. Ratings are their own feelings, and feedback always names what works plus one next step.

Where is a student's data stored?

Progress is saved only in their own browser on their own device. There are no accounts and no database. Clearing the browser or pressing "Start over" removes it. When the AI is on, the text a student types in an answer box is sent through our server function to Google's Gemini to get a reply. The game doesn't save it anywhere else.

Are the jobs real?

Each internship is based on a real job posting, with the employer renamed. The findings in each scenario are made-up practice data, and the game says so on screen.

How do we change the words or add a job?

Edit src/content/scenarios.json. Changing text needs no code. Adding a fifth building would need small code changes, mainly for the 3D building and room.

Does the AI cost money?

Not to students, and not to us while billing stays off. The live link uses one free Gemini key from Google AI Studio, so everyone shares its free daily limit. If it runs out, the game quietly uses its written lines until the limit resets.

What if the AI fails or someone tries to misuse it?

The server retries once for a hiccup, then falls back to the written lines, so students never see an error. Only the game itself can call the AI, each visitor is limited to 30 calls per 10 minutes, and every reply is checked before it is shown.

Architecture

How the code fits together

The app controller is the centre. It reads the content, runs the scenario steps, asks a feedback provider for the manager's words, tells the world what to show, and saves results through the store.

Separation

The game logic never touches three.js directly. It talks to a small World interface (enter, exit, setVisited, setTalking…). That's why Simple mode is a drop-in swap.

Providers

The manager's words come from a FeedbackProvider. ScriptedProvider reads the content file; AiProvider asks the AI server and falls back to the scripted one. Skill tags always come from the content file.

Scenario engine

A small state machine

Each visit to a building is a Run object that moves through fixed steps. Two steps are conditional.

intro→choose→write→coach?→follow-up?→feedback→reflect→rate→resources

  • ?coach appears only if the answer is clearly weak (checked by feedback/coach.ts, or by the AI). The student can revise up to two times; the first draft is kept.
  • ?follow-up appears only when the AI is on and the student wrote something.
  • ✓The attempt is saved at rate, so leaving during resources loses nothing. Leaving earlier asks for confirmation and discards the run.
  • ↺Each action can queue one manager reaction (pendingLine), which is spoken at the start of the next step.
  • ▤A task reminder and the findings card for the chosen approach stay on screen during write, coach and follow-up. The same findings are given to the AI.

Data

What gets saved

One JSON object in localStorage under the key careerPlaza.v2. Every read and write is wrapped so the game still works (from memory) if storage is blocked. Saves from the first version are cleared on load.

SaveState = {
  version: 2,
  attempts: Attempt[],      // one per finished scenario
  selfChecks: SelfCheck[],  // first = start check, later = retakes
}

Attempt = {
  scenarioId, choiceId, startedAt, isRevisit,
  writtenResponse, firstDraft?, revisions?, reflectionNote?,
  enjoyment: 1-5, confidence: 1-5, wantsMore,
  skills: [{ skill, weight }]   // weight 2 = main skill, 1 = also used
}

The growth record is never stored. record.ts rebuilds it from the attempts each time: skill totals, skills by building, gaps, "try next" and "Then and now".

3D engine

How the plaza is drawn

Built from code

No model or image files. Buildings, rooms and characters are boxes, cylinders and spheres. Signs, charts and floors are drawn with the canvas API at runtime.

Kept light

Trees, windows, grass and books use instancing (one draw call for many copies). Geometries and materials are cached by a Kit class and disposed when a room closes.

Light and shadow

Filmic tone mapping, a hemisphere light and one low sun, always in daytime whatever the device's theme. One soft shadow map, re-rendered only when something moves. Pixel ratio capped at 2 for phones.

Camera and motion

Eased camera flights into each door, an iris transition into the room, a slow idle orbit. With reduced motion on, these become quick fades, and the scene only re-renders when something changes.

If WebGL can't start, the game catches the error and switches to Simple mode automatically.

AI pipeline

From a student's sentence to a manager's reply

  1. The browser calls an AI route, for example POST /api/ai/coach, with the scenario, the choice and the student's text. The address is the same locally and online.
  2. Something on the server picks it up. Locally, a Vite plugin (server/ai-plugin.ts) does. Online, a Vercel function (api/ai.ts, routed by vercel.json) does. Both run the same shared core, server/ai-core.ts.
  3. Online, the function first checks that the request comes from the site itself (the Origin header), applies a per-visitor limit, and caps the request size.
  4. server/prompts.ts builds the prompt from the content file: the manager's personality, the task, the findings on screen, and the student's text inside tags marked as data.
  5. server/gemini.ts calls Gemini's generateContent with a response schema, so the reply comes back as fixed JSON fields. The key is sent in a header, never in a URL.
  6. The reply is checked: field lengths, questions ending in "?", and no code, links, tags, scores or "best fit".
  7. If something hiccups (a timeout, a server error, an empty reply or a failed check), the core retries once. It never retries a rejected key or the free limit. If it still fails, the route returns an error and the game uses the scripted line.

Limits

Inputs capped at 400 characters, bodies at 20 KB. Online: 30 AI calls per visitor per 10 minutes. Locally: 120 calls per run, 20 per minute. 12-second Gemini timeout per try; the browser waits up to 22 seconds so a retry fits.

Keeping it out of the scripted copy

A build flag, __AI_ROUTES__, is true under npm run dev and in Vercel builds, and false everywhere else. In the GitHub Pages build the AI calls are removed entirely. No build contains the key.

Known limits

Worth knowing

  • !Progress lives in one browser on one device. There's no sync, and clearing site data removes it.
  • !Frame rate on low-end phones hasn't been measured on real devices yet.
  • !On Google's free tier, prompts may be used to improve Google's products, and the live link sends what players type to Google. Use a paid key or an approved route before a real pilot with students.
  • !The live link shares one free Gemini key, so everyone uses the same daily limit. When it runs out the game uses its written lines until it resets. Keep billing off for the key so it can never charge.
